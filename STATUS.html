2 · Data flow

Source → infer (Script TOP, GPU inference on the cook thread) → union mask TOP, boxdata TOP (384 floats) and detections DAT → the GLSL outputs (overlay / chromakey / composite), which also take the full-res source.

Order of operations: open the TOX, run the tdPyEnvManager setup, then wire a source in. No installer script, no setup panel — the environment does the rest.

4 · Sync the TOX DATs

The .pyt files in python/ are the source of truth; the TOX carries them as DATs. After editing any of them, sync them back:

  1. Open rfdetr.tox — double-click the container to open it.
  2. Sync python/extension.pyt — paste into the infer Script TOP's Callbacks DAT.
  3. Sync python/callbacks.pyt — paste into the container's Callbacks DAT.
  4. Sync python/add_params.pyt — paste into python/add_params and re-run the Textport (idempotent — safe to re-run).
  5. Sync python/core.py — paste into python/core.
  6. Run the tdPyEnvManager setup — so .venv exists and is populated from requirements.txt.
  7. Save the .tox — right-click the container → Save As → rfdetr.tox.

5 · In-TD verification checklist

  1. State cycles init → loading → ready on the first cook; the status DAT ends on a [ready] line.
  2. Mask TOP is full-resolution 0/1 (subject region = 1, background = 0).
  3. boxdata TOP is 384 × 1, 32-bit float; unused slots stay zeroed.
  4. detections DAT has the header row class_id, class, confidence, x1, y1, x2, y2, area, frame plus one row per detection.
  5. Switching Model flips State to loading and the UI does not hang.
  6. Portability proof: rename the component to rfdetr2 in a scratch project — it still cooks.
  7. Drop the .tox into a brand-new empty project — it works with no path edits.
